# 设计与实现流程

本文维护视觉设计任务的推进方式；当前外观与交互要求见 [视觉规范](ui.md)，计划内容、状态与归档规则统一见 [计划与交付记录](plans/README.md)。

1. **了解现状**：先检查 Git 状态、受影响源码和现有规范，保留未提交改动。明确用户路径、四标签顺序、需要改善的问题和不变的功能契约。
2. **工具选型**：使用 React Bits MCP 搜索并阅读候选示例，记录准确组件名、来源、依赖和采用理由。优先复用公共控件与变量；原生页面先评估 CSS/JavaScript 适配，直接采用源码时核对许可。配置见 [开发工具](development.md)，已有选型见 [React Bits 选型依据](decisions/react-bits.md)。
3. **形成计划**：需要方案时按 [计划内容要求](plans/README.md#方案内容) 覆盖代码结构、与现有实现的对接及验证安排，不只描述视觉目标。小幅样式修正无需单独建计划。
4. **实施**：从最小范围修改；公共样式按现有入口级联，专属差异放功能目录。内容和操作不等待装饰；遵循[响应式布局标准](ui.md#响应式布局标准)的宽度依据、断点与重排方式，覆盖键盘、触屏、禁用、进行中及减少动态效果，保持真实任务生命周期。模块接入见 [前端开发](frontend.md)。
5. **验收**：按仓库约定选择[验证命令](development.md#验证命令)；按 [视觉规范](ui.md#适配与验收) 检查中英文、宽窄屏和状态矩阵，记录实际执行与未执行项目。性能目标须以同环境测量确认；浏览器模拟尺寸不能替代物理设备。
6. **归档**：按 [状态与归档](plans/README.md#状态与归档) 更新方案位置和验证记录，将生效的长期规则写入视觉规范，选型依据归入 `docs/decisions/`。仅仓库级约定变化时更新 AGENTS.md。
