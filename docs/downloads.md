# 下载任务与缓存

本文维护浏览器下载的本地生命周期、暂存、发布隔离和归档能力。接口路径与 HTTP 缓存有效期统一见 [接口参考](api.md)，页面构建接入见 [前端开发](frontend.md)。

## 任务生命周期

安装包与镜像的浏览器下载共用 `src/client/common/browser-download-task.js`，没有固定文件大小上限，受浏览器存储配额与磁盘空间限制。下载完成后本地打包，再自动触发保存。

| 类型 | 策略 |
| --- | --- |
| HTTP 缓存 | 网络响应的复用与有效期由响应头决定，具体接口策略见 [接口参考](api.md)；浏览器负责存储和回收 |
| OPFS 暂存 | 每次任务在 `dockerboost-downloads/<类型>-<任务ID>/` 创建独立目录；失败或停止后清理，触发保存后保留 60 秒再释放文件引用并清理 |
| 遗留目录 | 页面初始化、刷新安装版本、新下载前清理；兼容旧安装目录和旧镜像会话目录，支持 Web Locks 时跳过其他标签页正在使用的任务 |

浏览器无法通知网页文件已保存完毕，60 秒为保存交接缓冲。关闭页面可能中断定时清理，遗留目录由下次访问清理。OPFS 不保留长期复用缓存，重复下载加速依赖 HTTP 缓存。

## 自动重试

单个镜像、批量镜像与离线安装包的浏览器下载共用 `src/client/common/download-retry.js`。首次失败后依次等待 1、2、4 秒，最多自动重试三次（总计最多四次尝试）；任一次成功立即结束，第三次重试仍失败才显示最终失败。主动停止、停止全部或等待期间取消均不重试，并清除退避计时器。手动重新下载重新计算重试次数。版本目录与架构查询不属于下载重试。

每次重试前等待当前 Worker、流和 OPFS 任务清理完成，再创建新的下载任务，沿用现有保存与清理生命周期；重试从零开始，不实现断点续传。安装包每次尝试使用独立取消信号，中止并等待所有并行请求结束后清理。批量任务在退避期间保持运行状态和原有并发槽位，锁定参数且支持停止，最终失败后才计入失败汇总。进度 `retry(error, { attempt, delay })` 展示重试序号及等待时长，保留最后实际进度；下一次 `start(name, { preserveStartedAt: true })` 清除本次指标，但完成总耗时包含所有尝试和等待时间。

## 发布标识与请求隔离

构建按源码、静态资源及配置内容生成 8 位 URL 安全字符的发布标识，直接注入页面 JS 与下载 Worker，同时作为 JS、CSS、图标与 Hero 的统一文件名后缀；不再生成或请求 version.json。安装文件和镜像请求直接携带内嵌的 `version` 参数。同版本按对应 HTTP 缓存策略复用响应，新版本使用不同地址，不再复用旧版下载响应；旧 HTTP 缓存由浏览器回收，OPFS 仍按任务清理。相同源码重复部署保持相同标识。

## 哈希与归档实现

浏览器镜像归档同时包含 OCI 索引与 Docker manifest.json。OCI 描述符的 `io.containerd.image.name` 使用完整 Docker Hub 名称（例如 `docker.io/library/redis:latest`），`org.opencontainers.image.ref.name` 保存标签。containerd 优先读取 OCI 索引，不能依赖 manifest.json 的 RepoTags 修正短名称，否则可能出现导入成功但运行时找不到本地镜像的问题。

安装包增量 SHA-256 使用 @noble/hashes，经 src/client/common/sha256.js 适配。TAR 头、PAX 与填充由 modern-tar 编码，archive-format.js 负责业务条目、流式读写和取消；公共 OPFS writer 负责 close/abort。生产与消费均停止后才允许清理暂存。

## 接入下载功能

新增下载功能使用 `createDownloadTask(kind)` 获取 `id` 和 `directory`，下载与打包完成后调用 `save(archive, filename)`，在 finally 调用 `finish()`。使用后台 Worker 时，将任务 ID 传给 Worker；失败或停止后先终止 Worker，再结束任务。功能模块不自行维护目录命名、锁和清理定时器。文件写入共用 `opfs-file-writer.js`：流式下载使用 `writeOpfsStream`，打包使用 `writeOpfsFile`；公共函数负责关闭、异常中止和读取流释放，校验与进度由功能回调提供。

## 下载状态与进度展示

安装包与镜像下载复用 `src/client/common/download-progress.js` 和 `src/client/styles/download-progress.css`。展示模块接收现有任务的阶段、累计字节和总字节，管理文案、速率采样、ARIA 进度属性、文件详情及布局，不管理请求、取消、OPFS 或保存生命周期。

- `start(name)` 清除旧任务的速度和进度；准备、解析和未知总大小的下载保持零填充，新任务及零字节进度立即归零，不从上一状态回退过渡；`update({ phase, completed, total, name })` 更新阶段。准备、解析、打包和保存交接为不定进度；未知总大小的下载显示已接收字节，不提供百分比或 `aria-valuenow`。
- 下载阶段使用真实累计字节 / 总字节百分比，文字和进度条一致。达到 100% 仅代表下载字节收齐，随后显示独立的本地打包阶段，不再使用固定 90% / 95% 模拟整体进度。
- Worker 的 `done` 仅表示归档已就绪，展示映射为保存交接。调用 `task.save()` 成功后才调用 `complete({ filename, size })`，显示“已保存”（表示已交给浏览器保存）、归档大小与从任务启动到交接的总耗时。浏览器不提供最终磁盘保存完成通知。
- 速度只用于下载阶段；打包与交接不沿用旧速度。完成摘要不再把归档大小除以包含打包的总耗时称为下载均速。
- `fail(error, cancelled)` 统一失败和停止展示；紧凑批量模式失败时保留最后一次实际下载的进度条，将错误合并为上方单行，其他失败与主动停止隐藏进度并停止其动画。`info(message)` 用于版本就绪、镜像详情等非下载状态；`clear()` 隐藏状态区，两者均清除旧任务指标。
- `setLanguage(language)` 根据保留的状态重新渲染阶段、指标和耗时，不重置任务。原始异常诊断保留其来源文本。
- 常规字节更新合并到最多每 100ms 一次渲染；阶段、文件、总大小变化与最终字节事件立即展示。文件名单行显示，最大宽度为可用宽度与 72ch 中的较小值，超出部分使用省略号，悬停可查看完整内容；错误信息仍允许换行，不缩小字号；中英文和减少动态效果使用同一套公共规则。

## 批量镜像

下载页提供「单个 / 批量」切换。批量模式先尝试解析 Compose，失败时按每行一个镜像的列表解析，忽略空行、合并重复项并提示无效行。浏览器通过 YAML 库读取粘贴或选择的 Compose 文件（最多 1 MiB），提取 `services.*.image`，按镜像与显式平台合并关联服务；下载时再按最终镜像、平台与镜像源去重。用户逐项或全部将镜像加入队列，在队列中选择目标架构，镜像源固定为自动选择。Compose 中的 `platform` 作为初始偏好，允许用户在队列中显式修改。仅支持公开镜像，不执行 `build`；未展开变量、仅 build 的服务与 extends 显示问题，含 include 的配置无法作为 Compose 解析。复杂配置先使用 `docker compose config` 展开，支持的其他镜像仍可单独选择下载。

批量页面按配置输入、选择镜像、下载队列排列。粘贴或编辑配置后自动解析，选择或拖入 YAML 文件后立即解析；仅在本地读取，限制 1 MiB。Compose 输入框与候选镜像内容区均固定 300px 高，输入不折行并支持横向、纵向滚动，候选列表在固定区域内滚动，避免配置行数或镜像数量撑高双栏。候选镜像每行提供「加入下载队列 / 移除下载队列」切换，每个镜像保持一行，窄屏以加号 / 减号代替文字操作并保留悬停提示与无障碍名称，已入队以品牌色小勾标记；运行或排队中的任务需先停止并完成清理，候选区移除按钮与队列移除按钮同时禁用。解析出候选镜像后可使用「全部加入」添加尚未入队的镜像，不自动启动下载。候选列表按镜像与 Compose 平台标记已入队项；后续编辑或重新解析配置不会清空队列。队列使用「镜像名 → 架构 → 下载进度 → 操作」表头。镜像源固定自动选择，每项独立解析，不再提供源列表设置区。表头统一架构提供 linux/amd64 和 linux/arm64，任务内可选择解析出的全部平台与变体；统一设置优先精确匹配，否则匹配同一 OS / 架构的实际变体（例如 linux/arm64 对应 linux/arm64/v8），下载使用完整解析平台；Compose 或单项指定的变体必须精确匹配。表头初始显示「选择架构」，选择后统一应用于未运行任务及后续入队任务（优先于 Compose 平台）；任务内可单独调整，统一设置或 Compose 指定的架构不受支持时清空选择并显示任务提示和汇总提醒，禁止静默下载其他架构。表头主按钮在空闲时显示「开始下载」，队列有排队、运行或等待重试的任务时切换为「停止全部」；停止后等待任务清理结束再恢复。右侧「重新解析」对当前全部队列项重新获取镜像信息，清除旧下载状态、错误和进度，保留镜像顺序及架构偏好，不自动下载；空队列、解析中或下载未清理完毕时禁用。统一架构设置只影响未运行任务，排队和运行中的参数锁定。源列表、自动选源、镜像规范化与实际可用架构查询复用单个下载的 createImageSelection，每项独立持有状态，源目录请求共享。单项与全部重新解析仍使用自动选源，并强制重新请求架构信息，不复用上次查询结果；解析失败、无可用架构或架构不受支持时禁止下载，支持重新解析。开始下载仅提交已解析且架构有效的任务，避免同时运行相同最终参数的任务。移除任务会取消其未完成查询。

浏览器默认最多并发下载 5 个镜像；队列内每项有独立进度和两个居中文字操作：主操作根据状态切换下载、停止、重新下载或重新解析，另一个为移除，运行或排队中的任务停止并完成清理后才能移除。「开始下载」启动尚未下载和已停止项，不重复下载成功项；失败项通过行内主操作逐项重试；解析失败项重新解析，下载失败项重新下载，解析失败也计入失败摘要。候选列表限高滚动；队列支持批量停止。提示可折叠；终端下载区沿用单个模式的命令块与「复制全部」按钮，通过公共 data-copy 事件复用勾选、成功色和 toast 反馈。取消的任务完成 Worker/OPFS 清理后才释放并发槽位。单个与批量共用 `export-archive.js`，沿用公共下载任务、Worker、OPFS 和进度组件。每个镜像保存为独立 TAR；成功与失败项均保留在队列，支持逐项重新下载；停止单项只影响对应镜像，停止全部会取消活动任务及剩余队列。浏览器可能要求允许多文件下载。Compose 内容不上传，下载时仅发送选中的镜像参数。

单个和批量终端命令均获取静态 `/download-images.sh`，通过位置参数传入 `ORIGIN IMAGE PLATFORM SOURCE [IMAGE PLATFORM SOURCE ...]`；页面使用当前站点地址，批量按最终参数去重。脚本需要 `sh`、curl、jq、tar 及常见命令行工具。它通过 `/api/download-plan` 获取实际仓库、源和 blob 描述信息，再通过 Registry 接口下载内容；静态脚本由资产服务分发，元数据和文件流仍经过服务端接口。

最多同时处理 4 个镜像，每个镜像最多并发下载 3 个去重后的 blob（包括配置）；空闲任务位继续处理队列。单个 blob 的下载失败或长度不符时独立重试最多三次，依次等待 1、2、4 秒，等待期间占用该 blob 的并发位置。终端显示镜像开始、完成及重试信息，不显示并发 curl 进度表；按 Ctrl+C 取消运行中的任务。成功后检查每个 blob 的长度，并将每个镜像分别打包为 TAR；这不是对 blob 内容的 SHA-256 摘要校验。失败的镜像不会阻止其他镜像下载，全部处理后按输入顺序汇总成功及失败的镜像、平台和源，失败项附原因，并返回失败状态。脚本保护已有文件，在脚本所在目录创建隐藏的队列及镜像暂存目录，正常退出、失败和可捕获的中断时清理暂存及下载的脚本；SIGKILL 或断电可能留下文件，确认任务停止后需手动清理。保留旧 `/api/download-script` 供已有命令使用。

批量队列使用紧凑进度：下载时仅展示百分比（总大小已知时）、已下载大小 / 总容量、速度和进度条；总大小未知时显示已下载大小与未知提示，不重复阶段标题及镜像名。外层队列提示与进度组件互斥显示，直接跟随组件实际可见性，不依赖队列状态回调与进度更新的先后顺序。完成后在同一行交替展示「100% · 归档大小 · 总耗时」与「已保存 · 文件名」，所有完成项共用文档动画时间轴，同步淡入淡出和轻微位移；减少动态效果时静态展示两行并隐藏完成进度条。下载失败与等待重试时不再重复外层队列状态，错误或重试提示合并为进度条上方单行，进度条保留最后一次实际下载进度并停止不定动画；长详情省略并保留完整文本及悬停提示。紧凑指标保持单行，进度区固定为 54px（两行各 24px、间隔 6px），从待下载起预留，任务状态变化不撑高队列行。解析、打包、保存交接与错误仍保留明确状态，文件保存语义不变。


## 离线安装包终端下载

离线安装包的终端命令获取静态 `/download-docker.sh`，按 `ORIGIN ARCH DOCKER COMPOSE VERSION` 传入当前站点、架构、Docker 版本、Compose 版本和构建版本。脚本需要 `sh`、curl、jq、tar、sha256sum 及常见命令行工具，通过 `/api/install/plan` 取得包内文本，通过 `/api/install/asset` 流式获取二进制并生成 SHA256SUMS；二进制串行下载并逐项标注文件名；交互式终端显示单条进度条，非终端输出使用简洁状态，不显示进度表。二进制下载沿用 curl 的最多三次重试；在脚本所在目录创建隐藏暂存目录；正常退出、失败或 Ctrl+C 等可捕获的中断时清理暂存和下载的脚本。SIGKILL 或断电可能留下文件，确认任务停止后需手动清理。旧 `/api/install/script` 保留兼容。包内安装与卸载脚本仍由安装计划生成，配置页的配置命令也维持原有生成方式。

## 队列分享

下载队列右上角的「分享队列」在浏览器生成并复制当前全部队列项的链接，空队列禁用；「独立 TAR · 最多同时下载 5 项」放在标题下方。分享内容仅含镜像原始引用和每项平台（含完整变体），已解析项使用实际选择的平台，未解析或不支持的平台保留指定偏好；不包含 Compose 源文、下载状态、进度和临时文件。镜像源仍由接收方自动解析。

链接使用 URL fragment，格式为 `#download-batch?v=1&queue=<URL 编码的 JSON 二元数组>`；数组中的每项为 `[image, platform]`，空平台表示自动选择。编码长度超过 2048 字符时优先尝试浏览器原生 gzip，并在更短时改用 `#download-batch?v=1&gzip=<Base64URL>`。完全无状态，不调用分享 API、不在服务端保存队列。压缩格式参考 [Compression Streams API](https://developer.mozilla.org/en-US/docs/Web/API/Compression_Streams_API)。不支持压缩的浏览器使用可读格式；不支持解压时明确提示使用新版浏览器。

接收方打开链接即进入下载页的批量模式，完整校验后去重、入队并通过现有 createImageSelection 逐项解析；不自动开始下载，也不会静默切换指定架构。成功恢复后清除 URL 片段。版本、条目、镜像字符、平台及重复参数经过校验，错误链接不部分导入。每个分享最多 1000 项，片段上限 64 KiB，解压后的载荷上限 1 MiB，流式读取时执行限制；超限时明确提示。分享快照在点击时固定，不受之后的队列变化影响。
