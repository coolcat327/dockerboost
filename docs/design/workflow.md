# 设计与实现流程

1. **了解现状**：先检查 Git 状态、受影响源码和现有规范，保留未提交改动。明确用户路径、四标签顺序、需要改善的问题和不变的功能契约。
2. **工具选型**：使用 React Bits MCP 搜索并阅读候选示例，记录准确组件名、来源、依赖和采用理由。优先复用公共控件与变量；原生页面先评估 CSS/JavaScript 适配，直接采用源码时核对许可。
3. **形成计划**：涉及多阶段实施、选型取舍或后续工作的设计任务，在 `docs/plans/pending/` 写目标、范围、实现步骤、验收标准和风险；小幅样式修正无需单独建计划。长期规则归入 `docs/design/`，不把未验证目标写成产品能力。
4. **实施**：从最小范围修改；公共样式按现有入口级联，专属差异放功能目录。内容和操作不等待装饰；覆盖键盘、触屏、禁用、进行中及减少动态效果，保持真实任务生命周期。
5. **验收**：按 AGENTS.md 运行所需检查；浏览器检查中英文、宽窄屏和状态矩阵，记录实际执行与未执行项目。性能目标须以同环境测量确认；浏览器模拟尺寸不能替代物理设备。
6. **归档**：实现并完成对应验收后将计划移到 `implemented/`，写明结果与限制；未完成工作保留独立待实现计划。更新文档索引与 README 行为描述；仅仓库级约定变化时更新 AGENTS.md。

每份计划只保留一个状态，避免复制两份互相矛盾的方案。设计规范描述当前规则；调研记录来源与决策依据，计划记录交付边界与证据。
