# Workflow Demos 开发约定

## 阅读入口与职责

- 先遵循[仓库开发约定](../../AGENTS.md)。场景与主站流程的对应关系、工程边界和联动条件见[主站与流程演示](../../docs/architecture.md#主站与流程演示)。本文件补充动画工程的长期约束与最低验证要求。
- [简体中文 README](README.md) 与 [English README](README.en.md) 同步维护场景、目录职责和使用命令。按任务查阅相关源码与主站专题，核对操作和限制时以主站实现为准。
- 源码与配置是动画行为的事实依据。命令、目录或导出行为变化时同步两份工程 README，交付与验证记录留在提交或 PR。

## 工程边界

- 从最小必要范围修改。工程使用独立依赖和锁文件，沿用仓库的 Node.js 与 pnpm 版本及冻结锁文件安装约定。Remotion 和 React 依赖限于本工程，渲染按需执行。
- GIF 通过渲染入口更新。随仓库版本管理的是两份主 README 引用的 `docs/assets/workflow-demos/` 中的最终 GIF。渲染临时文件、预览缓存与依赖目录遵循仓库的生成文件约定。
- 新增场景时按领域组织实现，复用已有画面组件、色彩变量和时间轴。只有多个场景确实共用的逻辑才提取到共享模块。保留受影响文件的 TypeScript、TSX 与 CSS 风格。

## 场景与视觉一致性

- 同一场景的传统流程与 DockerBoost 使用可比的目标、示例数据和结果，沿用共同的三幕节奏。保留主 README 左侧传统流程、右侧 DockerBoost 的顺序。
- 标题、字幕和画面内可见文本成对维护简体中文与英文。以两种语言各自的阅读习惯表达同一含义，保留准确的命令、镜像名、版本和架构。示意界面可省略细节，功能步骤和使用条件应与主站一致。
- 沿用共用的标题区、舞台、字幕区及色彩变量。动效由帧位置驱动，保持预览与导出一致。共用时间轴、画布、转场或压缩参数有变动时，按成组输出评估节奏、清晰度和文件体积。
- 合成 ID 使用 `<scene>-<traditional|boost>-<zh|en>`，GIF 文件名使用 `<scene-slug>-<traditional|our>-<zh|en>.gif`。文件名前缀用小写英文短语描述具体场景，DockerBoost 版本使用 `our`。新增、重命名或移除场景时，按影响范围同步合成注册、导出映射、GIF 和两份主 README 的引用。

## 验证与交付

- TypeScript、TSX 或渲染配置改动至少在工程目录执行 `pnpm run check`。渲染入口、导出目录或参数变更至少实际导出一个合成，核对文件名、尺寸和目标路径。
- 画面、字幕或时间轴变更时，检查受影响场景的两种语言与两条流程。验收首帧、转场和循环接缝，并在 README 并排展示宽度下核对字形、对比度和裁切。共用画面或时间轴改动覆盖全部场景。
- 仅文档改动检查两种语言的内容对应、本地链接及差异。交付时说明实际检查和未执行项，并注明 AGENTS.md 是否需要同步。
